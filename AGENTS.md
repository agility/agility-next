# AGENTS.md

Operating guide for AI coding agents working in `agility-next`. Humans: see [README.md](README.md)
for usage and [docs/](docs/) for reference material.

## 1. The one thing that will trip you up

**The repository root is build output, not source.**

`index.js`, `node.js`, `utils.js`, `AgilityPic.js`, `*.d.ts` and friends at the root are all
generated by `tsc` and moved there by the build. They are **gitignored** (`.gitignore` ignores
`*.js` and `*.d.ts`) but they sit on disk next to the real files, so a directory listing makes them
look like source.

> **Never edit a `.js` or `.d.ts` file at the repository root.** Your change will be silently
> destroyed by the next `npm run build`, and it will not be committed because the file is ignored.

**All source lives in [`src/`](src/) — and nowhere else.** The only tracked, hand-written files are:

```
src/index.ts        src/node.ts        src/config.ts      src/types.ts
src/ContentZone.tsx src/AgilityImage.tsx  src/AgilityPic.tsx  src/isSvgUrl.ts
src/browser.js      src/utils.js       ← hand-written JavaScript, genuinely source
```

`git ls-files` is the fastest way to confirm what is real. If a file is not in that list, do not
edit it.

## 2. What this repo is

`@agility/nextjs` — the npm package that lets a Next.js app render pages, content zones and images
from [Agility CMS](https://agilitycms.com). It is a **thin integration layer**, not a client:
all HTTP work is delegated to the `@agility/content-fetch` SDK (a peer dependency). This package
supplies the Next.js-shaped wrapper: page-props resolution, static path generation, preview-mode
plumbing, a content-zone renderer and two image components.

It is a **library published to npm**. There is no app to run, no dev server, and no test suite.

**Versioning is coupled to Next.js.** The major version tracks the supported Next.js major:
`16.x` → Next 16, `15.x` → Next 15, `14.x` → Next 14. Do not bump the major for a feature; a
major means "this now targets the next Next.js".

## 3. Commands

| Command | What it does | Notes |
|---|---|---|
| `npm install` | Installs deps **and runs a build** | `prepare` hooks into install |
| `npm run build` | `tsc` → `dist/`, then moves `dist/*` to the root and deletes `dist/` | The only verification that exists |
| `npm run clean` | `git clean -Xf` | ⚠️ Deletes **every** ignored file — build output *and `node_modules/`*. You will need to reinstall. |
| `npm test` | Exits 1 | There are no tests. Do not report a passing test run. |

**Verification bar for any change:** `npm run build` must complete with no TypeScript errors, plus
a manual render check of the affected component. There is no automated safety net — say so plainly
when reporting work rather than implying tests passed.

## 4. Architecture in one pass

Two entry points, and the split matters:

```
@agility/nextjs          → src/index.ts  → components, types, config, browser + utils helpers
@agility/nextjs/node     → src/node.ts   → server-only data fetching (uses crypto, process.env)
```

`package.json` has **no `exports` map**. The `@agility/nextjs/node` subpath resolves purely by file
layout — `node.js` must physically exist at the package root. That is the reason the build moves
`dist/*` to the root instead of shipping a `dist/` folder. If you ever add an `exports` map, the
build layout has to change with it, and vice versa.

| File | Role |
|---|---|
| [`src/node.ts`](src/node.ts) | Server data layer. `getAgilityPageProps`, `getAgilityPaths`, `getDynamicPageURL`, `validatePreview`, `generatePreviewKey`. Never import this into a client component. |
| [`src/config.ts`](src/config.ts) | Reads all `AGILITY_*` env vars into `agilityConfig` **once, at module load**. |
| [`src/types.ts`](src/types.ts) | Every public type. The package's real API contract. |
| [`src/ContentZone.tsx`](src/ContentZone.tsx) | Maps a page zone's modules to React components via the consumer's `getModule`. |
| [`src/AgilityImage.tsx`](src/AgilityImage.tsx) | `next/image` wrapper with an Agility CDN loader. **`"use client"`** — App Router consumers must use it from a client component. |
| [`src/AgilityPic.tsx`](src/AgilityPic.tsx) | Renders a raw `<picture>`. No client boundary, so it is the App Router–friendly choice and the one to recommend. |
| [`src/isSvgUrl.ts`](src/isSvgUrl.ts) | Internal helper shared by both image components. Parses the URL so `logo.svg?v=2` is still detected. Not exported publicly. |
| [`src/browser.js`](src/browser.js) | `handlePreview` — browser-side preview redirect. |
| [`src/utils.js`](src/utils.js) | `renderHTML`, `cleanHTML`, `asyncForEach`, `expandContentItem`, `expandContentList`, `expandLinkedList`. |

See [docs/architecture.md](docs/architecture.md) for the full request flow and
[docs/api-reference.md](docs/api-reference.md) for every export.

## 5. Code conventions

Match what is already there; this codebase is not uniform and that is fine.

- **Indentation is mixed, per file.** Match the file you are editing; do not normalise across files
  in an unrelated change.

  | Tabs | 2 spaces |
  |---|---|
  | `node.ts`, `AgilityPic.tsx`, `AgilityImage.tsx`, `ContentZone.tsx`, `utils.js` | `types.ts`, `config.ts`, `browser.js` |

  (Open PR #33 reformats `AgilityPic.tsx` from tabs to 2 spaces. That PR is not being merged — see
  §7 — so keep tabs in that file.)
- **No semicolons** in the `.tsx` components; **semicolons** in `node.ts`, `types.ts` and
  `config.ts`. Again: follow the file you are in.
- **`import React from "react"` is mandatory.** `tsconfig.json` sets `"jsx": "react"` — the classic
  runtime, not `react-jsx`. Omitting the import compiles to a `React is not defined` runtime error.
- **`target: "es5"`.** Avoid syntax that bloats or fails to downlevel. Optional chaining and
  nullish coalescing are fine (TypeScript downlevels them).
- **TypeScript is pinned to `4.9.3`** while React 19 and Next 16 types are modern. `skipLibCheck`
  is on, which hides the resulting friction. Do not casually bump TypeScript — it is load-bearing.
- **`src/browser.js` and `src/utils.js` are plain JavaScript on purpose.** `utils.js` uses CommonJS
  `module.exports` while `index.ts` re-exports it with ESM `export *`; that works through
  `allowJs` + `esModuleInterop`. Converting them to TypeScript is a real change with real risk —
  not a cleanup. Do not do it as a drive-by.
- **`tsconfig.json` includes are non-recursive** (`./src/*.ts`, not `./src/**/*.ts`). A file in a
  new `src/` subdirectory **will not be compiled**. Keep `src/` flat, or update the globs
  deliberately.

## 6. Environment variables

All read in [`src/config.ts`](src/config.ts) at module load. A consuming app sets these; this repo
never reads a `.env`.

| Variable | Default | Purpose |
|---|---|---|
| `AGILITY_GUID` | — | Instance GUID |
| `AGILITY_API_FETCH_KEY` | — | Live/production content key |
| `AGILITY_API_PREVIEW_KEY` | — | Preview content key |
| `AGILITY_SECURITY_KEY` | — | Signs and validates preview keys |
| `AGILITY_LOCALES` | `en-us` | Comma-separated; `[0]` is the default locale |
| `AGILITY_SITEMAP` | `website` | Channel name |
| `AGILITY_DEBUG` | `false` | `"true"` enables verbose logging |
| `AGILITY_FETCH_CACHE_DURATION` | `60` | Seconds. **`0` switches every fetch to `cache: "no-store"`.** |

Because `agilityConfig` is captured at import time, changing `process.env` after the module loads
has no effect. Anything that needs to vary per request must be a function argument, not an env read.

- **`AGILITYPIC-HANDOFF.md`** (repo root) — six proposed `AgilityPic` fixes ported from the 2026
  website fork. **Fixes 2, 3, 5 and 6 shipped in 16.0.9** (SVG bypass, `alt` handling,
  `fetchPriority`, null guard). **Fixes 1 and 4 remain outstanding**: `width`/`height` for CLS,
  which can move layouts and needs a minor plus a scoping decision, and the hi-DPI `srcSet` work.
- **PR #33 "Fix fallback width"** — OPEN, **do not merge; superseded by 16.0.9.** It carries three
  measured regressions: `&h=NaN` / `&w=NaN` on single-dimension sources, a broken upscale guard, and
  an `<img>` fallback serving the full-size original with no `format=auto`. It is `CONFLICTING`
  against `main` and based on `15.0.7`. Its one good line (`alt ??`) is now in `main`. See the
  addendum in `AGILITYPIC-HANDOFF.md` for the measured outputs, and ask Kevin what symptom he
  originally hit — the PR's premise does not hold up, so the cause is likely something else.
- **Issue #31** — `ImageField` types conflict with what the API really returns (`label` and
  `target` come back `null`). Directly contradicts the handoff's "don't loosen `ImageField`" advice.
- **Issue #32** — `AgilityPic` should accept gallery image items, which carry
  `metaData.pixelWidth/pixelHeight` as strings and have no `label`.
- **Issue #1** — "Needs to be properly documented", open since 2021. The `docs/` tree and README
  rewrite address it.
- **PR #10** — optional per-call channel name, open since 2022.

## 8. Known rough edges

Real defects found while documenting. None are fixed; do not assume otherwise. Confirm before
acting on any of them.

1. **`expandContentList` does not await its work** ([`src/utils.js`](src/utils.js)) — it calls
   `asyncForEach(...)` without `await`, so it resolves before the expansion finishes. Callers
   receive unexpanded items.
2. **Home-page resolution is positional** ([`src/node.ts`](src/node.ts)) — `path === "/"` takes
   `Object.keys(sitemap)[0]`, the first key in the sitemap, rather than looking up the actual home
   page. Reordering the sitemap can change which page renders at `/`.
3. **`handlePreview` guards on `process.browser`** ([`src/browser.js`](src/browser.js)) — a legacy
   webpack/Next 9 global. Whether modern Next still defines it needs verifying; if it does not, the
   function returns `false` and preview never activates. **Unverified — test before claiming
   either way.**
4. **`AgilityPic` emits no `width`/`height` on its `<img>`** — so it contributes layout shift on
   every image. This is handoff fix #1, still outstanding, and the one that needs a scoping
   decision rather than just a patch.
5. **`getAgilityPaths` logs unconditionally** — `console.log("... *** USING REST API ***")` on
   every call, ignoring the debug flag. Noisy in consumer builds (related to issue #25).

## 9. Release

Full runbook: [docs/releasing.md](docs/releasing.md). In short: bump `version` in `package.json`,
`npm run build`, verify, `npm publish`. `prepare` means `npm publish` builds automatically — but
build locally first so you see the errors.

Semver here is about **consumer-visible rendering**, not just API shape. A change that alters the
HTML an existing site emits (new attributes on `<img>`, different `src` query strings) can move
layouts and deserves a minor, not a patch.

## 10. Reporting your work

- Never claim tests passed. There are none.
- If you ran `npm run build`, say so and paste the real result.
- If you changed a component's output, state exactly which attributes or URLs changed, because
  that is what determines the version bump.
- Flag anything you could not verify rather than smoothing over it.
